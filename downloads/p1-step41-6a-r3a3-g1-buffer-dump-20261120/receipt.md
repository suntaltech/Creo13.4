## P-B1 · 动态缓冲

在原有 `smt6a_text` 的 `ProMessageToBuffer` 返回后，向原 JSONL 通道追加 `SMT_CONV_BUFFER_DUMP`。按调用来源登记 `model_name`、`detail`、`feature_name`。创建前的消息预检仍按原路径执行，预检结果不混入反馈采样。原有 `ProMessageDisplay` 的参数、调用次数和分支保留，原有模型调用、终态字段、事件结构和命令注册保持原样。

原始 SDK 返回码保留。0 和 -32 时，最多扫描 `PRO_LINE_SIZE=81` 个宽字符单元，超范围或未终止时不编码该缓冲。SDK 报 -32 且缓冲有效时，可以记录可见的截断片段。其他返回仅记录状态，缓冲字段用 null。有效缓冲沿用 `quote_message_utf16` 产生 JSON `\uXXXX`，不对 SDK 缓冲做 CP936 或 GBK 二次解码。参数来自原有 UTF-8 或 ASCII 路径，`param_kind=zh` 表示现有参数含非 ASCII 字节。日志超容量只报告诊断失败。没有解释空间的匹配字段保留为 null，离线验收时再判定。

`placeholder_remaining` 只描述已观察的缓冲中是否出现字面 `%0s`；判断替换成功时，还要核对完整实际文本、预期参数和截断标记。一个截断样本即使不含字面占位符，也不能作为完整替换通过的证据。

## P-B2 · 静态缓冲

已实现。原有 SUCCESS、MODEL_NAME、FEATURE_NAME 各自显示成功后，额外执行一次相同静态键的只读 `ProMessageToBuffer`，不传额外变参，也不再次调用 Display。静态诊断异常由探针自身捕获，不改变原反馈返回状态。

实际基线将“模型名称：”和模型名分片通过不同的消息调用发出。按同一 `operation_id`、`seq`、角色和键，离线重组语义上的“前缀＋中文名”，同时保留每条原始缓冲。此证据可核验前缀和替换文本，无法证明状态栏曾在同一帧显示拼接后的整句。界面结论仍依受控会话截图。
