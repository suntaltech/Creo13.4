## 工具交付

工具 tools/audit_sample_contract.py 使用 Python 3 标准库，只读选定 ZIP 和最多两个显式指定的头文件，输出派生 JSON 和散列。不会解压文件到 SDK，不执行 makefile、MSBuild、样例代码、cl/link/dumpbin，也不会加载 DLL、注册应用、启动 Creo、写 config.pro 或访问模型。

可在已有 Python 3 的离线工作机或云端使用；无需为此在 Creo 现场安装 Python。没有现成解释器时，保留原始样例资料交后续离线审核即可。本轮未取得真实样例 ZIP，工具的真实 SDK 审核结果尚未产生。

示例（路径均为占位符，输出目录必须是新的独立目录）：

```sh
python3 tools/audit_sample_contract.py --sample-zip "<真实protk_install_example.zip>" --dll-header "<真实ProToolkitDll.h>" --dll-header "<真实ProToolkit.h>" --export-log "<本次exports.log>" --output-dir "<新的离线审核目录>"
```

工具保留配置条件摘要，将 Debug 和 Release 条目分别列出；不求值项目导入、make 变量或条件表达式。它只报告文本中的导出候选及其与当前日志的差异，不会将所有 .def 文件的并集当成本项目必需导出。原始项目如果引用 ZIP 外的文件，需人工跟进该实际引用。没发现候选、解析有问题、达到上限或未求值条件都不能解释为“SDK 契约已满足”。输出不包含源代码全文、绝对安装路径或 PE 地址。

## 离线审核后如何最小修正

| 审核结果 | 后续动作 |
| --- | --- |
| 原样例明确要求当前链接遗漏的导出、引导对象或选项 | 仅补这一项，保留用户入口诊断，隔离重建并审核新 DLL 身份/导出/依赖。不要用 /FORCE、猜符号或强拉全部库替代原文依据。 |
| 原文明确表明参数类型/方向不同 | 只按该原文修正 ABI/缓冲区处理，重新审核。不凭泛化启动错误写入猜测的 version/build 字符串。 |
| 契约对比没有发现差异 | 再考虑补全诊断通道证据或实际装载错误详情，不能把“无差异”当成运行已通过。 |
| 资料缺失、条件未求值或原始链接命令不完整 | 保留未决项；不生成正式修复 DLL，不要求现场部署。 |

若已有隔离二进制审核环境，还可只读核对诊断 DLL 的实际导入函数及诊断 tag，以加强“源码—二进制”的身份联系；仅 KERNEL32.dll 这一 DLL 名称不够。此项仍不加载 DLL、不调用用户回调，不由本包自动执行。
