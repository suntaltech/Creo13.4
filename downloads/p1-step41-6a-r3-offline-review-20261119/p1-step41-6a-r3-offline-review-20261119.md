# P1 Step41 6A R3 离线 SDK 契约复核

2026-11-19 · 基线 `b99692e3f927ff297941e812e36ac5646bd323b7` · Creo 13.4.0.0

## 结论与身份对账

八项离线复核已完成。现有证据支持保留创建链和守卫。中文乱码已缩小到自定义消息的加载、缓冲解码或显示链路，现阶段缺少确定编码整改所需的证据。本轮交付契约复核与探针方案，未生成源码整改 diff。

从 GitHub 取回固定提交的补丁与清单，校验并应用到四个文件哈希相符的冻结 R2-B 副本。五个派生文件的字节数与 SHA-256 全部匹配，源码的 `SMT_CONV_RETURN` 29 个字段与输入单 §5 顺序一致。输入单与机读 JSON 的 DLL、DAT 身份登记一致，DLL 登记还与 6296 回传相符。1912 的 17 项中 2 项 VERIFIED、15 项 UNVERIFIED，及其正向创建样本，均按本机输入单引用。云端未收到 1912 原始 JSONL、DLL 或 DAT，无法独立验证其身份和运行记录。

依据包括冻结候选源码、已提供的《SDK 契约摘录汇编》§1–4 和受控头文件摘录。云端代理对 PTC 在线帮助的请求返回 403。下列结论注明了仅由签名或现场样本支持的边界。

## I-1 · 异单位换算与单位名

- 同版摘录 `ProMdlUnits.h:262/504/524–526/344–346` 给出主单位制、当前长度单位、`ProUnitInit` 以及 `ProUnitConversionCalculate(unit_from, unit_to, …)`。代码以解析出的 mm 为源、模型实际长度单位为目标，使用 `value_to = value_from * scale + offset`，与参数顺序及摘录的换算口径一致。`ProMdlUnits.h:159–164` 说明 offset 仅用于温度换算，长度 offset 为 0。保留有限正 scale 和有限零 offset 的门，避免把未经解释的非零偏移计入板厚。
- 查主单位制失败、当前长度单位缺失、mm 名称无法解析、空名、名字无法编码或因子无效，均沿用 `UNIT_UNSUPPORTED`。单位字段默认是 JSON 字面 `null`，只有整组名字及因子可序列化时才提交。无需以单位列表首项或猜测别名降级到创建流程。
- 两条 mm→mm 样本都不能判别方向。用独立只读探针在已确认长度单位为 inch 的零件上输入 1 mm，配对 `SMT_CONV_UNITS` / `SMT_CONV_RETURN`，预期 scale 约 0.03937007874015748、offset 0，换算样本约 0.03937007874015748 inch。记录实际单位名、因子、SDK 返回和硬停，不用正向创建补这项。

## I-2 · 特征类型和驱动面元素树

- `ProSmtDrvSurf.h` 注释树、`ProFeatType.h` 及 `ProElemId.h` 摘录支持当前选择。根 `PRO_E_FEATURE_TREE(386)` 下按候选顺序挂接 `PRO_E_FEATURE_TYPE(387)=PRO_FEAT_DATUM_SURF(942)`、`PRO_E_STD_FEATURE_NAME(1964)`、`PRO_E_DTM_SRF_TYPE(1131)=PRO_DTM_SRF_AS_WALL(15)`、`PRO_E_SMT_CONV_BODY(6612)`、`PRO_E_SMT_DRV_SURF(5111)` 和 `PRO_E_STD_SMT_THICKNESS(3332)`。
- 942 是 `ProFeatureTypeGet` 返回的特征族。其与 AS_WALL 子类型及默认体 `IsSheetmetal=true` 一同支持当前样本的驱动面转换路径。942 本身不足以确定最终钣金壁语义，也没有证据支持替换为其他特征枚举。保持节点、顺序和方向元素边界。
- 后续在既有授权的无保存样件上，查 Creo 特征信息或模型树类型、钣金属性及壁厚，关联到同一个返回特征 ID。若需 SDK 元素回读，先以本机 13.4 头文件核验读取和释放契约，之后单独设计只读探针。

## I-3 · 中文消息乱码

- 从发布补丁复算中文资源为 2,369 字节、UTF-8 无 BOM。使用 GBK 和 GB18030 直接解码均失败。两种语言各 30 条，键顺序一致，均采用四行记录和 `#/#`。早先 B 探针使用空占位行也报告中文乱码，因此无法将 `#` 定为根因。
- `ProMessage.h:10/106–119` 摘录说明调用和错误码，未说明资源文件编码或 BOM。守卫的乱码出现在无格式参数的 `smt6a_message → ProMessageDisplay` 之中，发生在名称展示之前；该现象不由 `%0s` 或 `smt6a_show_name` 的 UTF-8 转码触发。名称走动态参数的窄字符串链路，可能另有参数解码问题。`smt6a_quote_wide` 用于 JSON，不为状态栏加载资源。当前 `ProMessageToBuffer` 预检只判断返回码，未检查返回的 UTF-16 实际内容。
- 只读探针复用 `entry.cpp` 已有的 `probe_one_message`/UTF-16 记录方式。固定语言、内容、键和记录布局，分别用独立文件名，测试现有 UTF-8 无 BOM 与本机 SDK 样例采用的编码或 BOM。对同一中文静态串比较预期 UTF-16 代码单元、`ProMessageToBuffer` 返回缓冲和状态栏显示。静态串确认后，再分别用 ASCII 和已知中文参数测 `%0s`。独立文件名可避免旧消息缓存混入。每次只改变一个变量，并保留原 usascii 文件哈希作为对照。
- 如果缓冲在静态测试中已乱码，优先核查资源加载和解码。缓冲正确而状态栏乱码时，核查显示层。只有动态中文错误时，核查格式参数的编码契约。缺少上述运行结果和本机语言样例，暂不能把 GBK、BOM 或加载方式当作修复方案。

## I-4 · MODEL_READ_ONLY

- `ProFeature.h:460` 摘录确认 `ProFeatureWithoptionsCreate` 可返回 `PRO_TK_CANT_MODIFY`。当前仅在该真实返回下报 `MODEL_READ_ONLY`，保留其 SDK 原始码及创建已调用的事实。Windows 文件只读属性只说明文件层限制，1912 回传的内存创建已证明该属性不足以预测本动作的会话可修改性。
- 会话只读、受保护对象或当前操作受权限限制是待核验情形；现有资料未确认具体前置查询的函数签名和保护条件。保留现有判定。先用本机已确认的会话权限状态或 SDK 支持方式准备受保护样件，再另行审批最小验证，只按实际返回值记结果。

## I-5 · NO_BODY 与默认空体

- `ProSolidBody.h:52` 摘录的 `ProSolidDefaultBodyGet` 输出默认体句柄。空白零件成功取得默认空体，与“取默认体失败”不同。取到句柄并不能证明存在可选实体面。该样本后来走选面取消，归类正确。
- 摘录只有签名，未证明 `GENERAL_ERROR` 的唯一含义是“无默认体”。目前 `GENERAL_ERROR → NO_BODY`、其余错误到 `WRAP_SOLID_FAILED` 是候选分类，诊断时要保留原始 SDK 码。无法据此发明新的体积或几何前置查询。
- 在空白、纯曲面和普通实体对照件上，用只读方式记录默认体 getter 的返回值、有效句柄及经核对的体枚举或表面遍历结果。纯曲面件也可能带默认空体，需看实际返回。即便遍历没有面，仍要分别记录为空体、遍历失败及 getter 失败，避免把空体改归为无体。

## I-6 · INVALID_THICKNESS 兜底

- `ProMessage.h:265` 用 `range[2]` 指定上下界，ESC 可返回 `PRO_TK_MSG_USER_QUIT`。1912 的越界数值由 SDK 重输界面拦截，后来 Esc 的实际返回是 -31，归为 `CANCELLED`。插件拿不到被界面拦截的临时数值。
- 保留 0.1–20.0 mm、有限值、SDK 成功码三项后端防御，并保留独立 `INPUT_FORMAT_FAILED`。在当前 GUI 未触发兜底并不证明它不可达，也不需要另增“重输时取消”的结果码。无源码变动。

## I-7 · surface 选取过滤

- `ProSelection.h:453` 的 `option[]`、`max_count` 是选择器过滤参数。现场 `surface` 和上限 1 拦截了棱边、基准及多选提交，同时 B 样条曲面可以提交后由非平面守卫拒绝。SDK 摘录还允许无选择时成功返回并给出 `count=0`，所以应保留空选分支。
- `ProSelectionModelitemGet`、`item.type==PRO_SURFACE`、`item.owner==model` 与空指针/数量检查分别保护读取、归属和几何类型。保留这些检查，维持原过滤器。现有材料不支持用额外 filter 组合放宽转换入口。

## I-8 · 多体面归属

- `ProSolidBody.h:82` 的访问输入是指定 `ProSolidBody*`，当前只访问默认体。先核对选面 `PRO_SURFACE` 和模型 owner，再以 `ProSurfaceIdGet` 与选择项 ID 对账。只有遍历成功且恰有一次匹配才继续。无匹配、多匹配或遍历错误均保守报 `FACE_BODY_MISMATCH`。因此该码本身无法证明选面属于哪个非默认体。
- 默认体限定下无需扫描所有体来放行。两次拉伸仍为同一体，不能代替多体测试。真多体探针用明确具有两个独立实体体的零件，对默认体与另一体各选一平面。在本机头文件确认体枚举接口和释放规则后，可逐体用 visit 记录 body ID、surface ID、匹配数和原始返回，验证模型内面 ID 的区分能力。已有 B 探针的 E_NOT_FOUND 样本仅证实拒绝路径；当前不扩大候选能力。

## 交付边界

现有两条正向创建样本、已验证守卫、终态字段和结果码继续作为冻结基线。15 项现场未验证用例保持原登记，创建段 C 类失败分支按输入单仅留待自然出现时取证。此次未重编 DLL、未执行 Creo 或保存模型，仓库未推送。后续一旦取得消息解码或 SDK 错误语义的直接证据，再以本机审核过的最小整改包进入身份、静态、编译和 dumpbin 验收。
