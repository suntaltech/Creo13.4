# P1 Step34：最小 DLL 受控加载/停止准备包

日期：2026-11-09。判断：可以准备现有空 DLL 的一次受控加载/停止观察。本轮仅生成临时注册示例、观察记录模板和核查日志，不修改 config.pro、不自动启动 Creo、不注册或加载 DLL、不操作或保存模型。

## 四项答复

| 问题 | 结论 |
| --- | --- |
| 空 DLL 能否进入受控加载/卸载 | 可以进入一次验证准备；按用户报告，链接退出 0、DLL 存在且导出两个入口。执行前核对上轮 headers 输出确为 x64 DLL，并固定本次 DLL 的 SHA256；本轮未收到 DLL 原件，不能报告已独立验证 PE 或已经加载。 |
| 临时 protk.dat 怎么写 | 见 registration/protk.dat.example.txt。只保留单一具名条目、DLL 启动方式、实际路径及生命周期属性；不写入 config.pro 或自动启动配置。 |
| 是否先加文件回调日志 | 首次只验证应用状态时，不必，建议保留已通过链接的空 DLL。若验收目标是“直接证明两个入口均被调用”，则现有空入口证据不够，应先补仅诊断的标记或使用可靠调试证据，重新构建/检查后再做那一轮验证。 |
| 观察与失败处理 | 记录注册/加载前后及停止后的状态、实际提示、操作时间与响应；失败即结束本次尝试，保留证据，不自动重试、解锁、换库或强制终止进程。 |

这里的“可以准备”不是运行成功保证，也不是对精确 PTC 编译器补丁或许可证条件的认证。来源为用户的本机结果摘要：Step33 包哈希 MATCH，链接退出 0，p1_entry_minimal.dll 生成，dumpbin 导出 user_initialize/user_terminate，直接依赖仅 KERNEL32.dll，尚未注册或启动 Creo。云端未收到 DLL、散列或原始 dumpbin 输出。

空入口不引用业务 API，链接器可能未提取某些 PTC 库成员。因此只有 KERNEL32.dll 这一直接依赖并不矛盾，也不能证明后续 API 所需依赖已验证。不要为增加依赖项而盲目强制拉入全部库；/dependents 也不能单独证明实际加载条件。

## 临时注册文件

```text
name p1_native_entry_step34
startup dll
exec_file @VERIFIED_DLL_ABSOLUTE_PATH@
text_dir @EXISTING_LOCAL_TEXT_DIRECTORY@
allow_stop true
delay_start false
end
```

包内文件保留 .example.txt 后缀，含两个不可直接使用的占位符。下一轮在本地副本填入本次已核对 DLL 的绝对路径，以及实际存在的本地 text 目录，再保存为临时 protk.dat。优先使用无空格路径；如路径含空格，按本版官方注册样例核对写法。当前空入口无消息资源，但保留 text_dir 便于与已有候选模板一致，不把未核实的省略规则当成最小字段结论。

name 使用独立名称，不覆盖现有 Java/P1 应用条目。allow_stop true 表达允许提出停止请求，不保证停止必成功或 Windows 必然移除模块。delay_start false 表达不延迟初始化；实际注册/启动的触发时机须以本版行为为准，不能假设“注册一定没有执行任何入口”。该模板沿用此前同步 DLL 候选字段，尚未在本机 Creo 13.4 实际注册验证。

## 一次观察的范围与顺序

1. 使用人工准备好的空模型会话，确认没有已打开模型或未保存工作；不由脚本关闭现有模型或启动 Creo。核对 DLL 身份、x64 DLL 标记及两个精确导出名，保留当前 DLL 和注册副本，不在加载期间重编或替换文件。
2. 开始记录后，再使用本版辅助应用界面支持的临时显式注册/启动方式，选择该单一条目；不更改 config.pro，不启用全局自动加载。注册本身可能触发初始化，若已进入运行状态，不再补一次 Start；把注册/启动视为同一次加载尝试。
3. 记录准确提示、应用列表实际状态和界面响应。仅“注册条目出现在列表”不等于 DLL 已运行；如状态不明确，记录未知，不连续点击以试出结果。
4. 若应用已明确运行，人工提出一次停止/卸载请求，记录返回提示、列表状态和界面响应。若加载本身失败，则不把未发生的停止动作记录为成功；只有本版界面需要且明确提供单独卸载操作时才据其实际语义执行，不能盲目追加多次操作。
5. 完成后记录最终状态并结束本轮。保持无模型操作、无保存。临时条目是否可移除以本版界面及停止状态为准，不删除仍被加载的 DLL，也不改现有启动注册路径。

不提供自动加载脚本，不调用 LoadLibrary 代替 Creo TOOLKIT 注册验证。应用状态为“已停止”不等于直接观测到 user_terminate，也不等于 DLL 已从操作系统地址空间卸载；这些结论分别填写，不互相替代。

## 文件日志是否先加入

推荐先用现有空 DLL 完成最小应用状态观察，减少新增变量。本轮不修改入口、不重新编译或链接。如果下一轮明确要求两个入口的直接证据，再增加仅写本地诊断标记的代码，分别记录 initialize/terminate 进入与返回；不得在 DllMain 中做文件日志，不加模型、菜单或转换调用。

加日志后它已是新的二进制，必须重新生成对象、链接、核对导出和依赖并记录新的 SHA256，不能沿用本轮旧 DLL 的身份。日志路径必须预先明确、可写且不含模型数据；日志写入失败应单独记录，不能从“没有日志文件”反推出入口未调用。文件日志可能改变依赖清单，应以重建后的实际输出为准。本包不附诊断补丁或伪造回调日志。

## 失败时如何处理

| 实际现象 | 本轮处理 |
| --- | --- |
| 注册文件或路径被拒绝 | 保留原提示，核对该副本字段、文件存在性和路径写法；结束本次尝试，不写 config.pro 绕过。 |
| 找不到模块、位数或依赖错误 | 保留原提示及已保存的 headers/dependents 结果；不随机复制系统 DLL、不混入 MD/异步库。 |
| 出现开发/运行授权或解锁提示 | 原样记录并核对适用官方流程；不凭 _NU 后缀认定免授权，不自动尝试解锁命令。 |
| 注册后不明确、初始化报错或界面不响应 | 记录最后操作、时间、提示与响应状况，不连续点击或自动重试，不推断具体根因。 |
| 停止失败或状态仍在运行 | 保留状态，结束自动推进；不强杀进程、不删除/覆盖模块，也不将其写成卸载成功。 |

若发生异常，本轮结果是具体失败阶段或未决，而不是整个原生路线失败。只有核对证据并形成下一项针对性修改后再进行新的尝试。
