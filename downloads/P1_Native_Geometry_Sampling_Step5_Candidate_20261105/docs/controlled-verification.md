# 后续受控验证清单

本包未部署、注册、运行Creo或执行模型API。以下核对仅供后续既有受控授权范围使用，不自动执行现场操作。

1. 校验ZIP.sha256、SHA256SUMS、manifest、本机SDK及12个class/薄JAR身份。独立新目录/Step5类/命令，不覆盖旧插件或生产注册配置。Java25运行，SDK/JDK不随包。注册模板路径占位符不可直接用，不写Ribbon持久化。
2. 记录实际加载类/JAR、消息与测试注册文件散列。确认新命令Sample Read-Only Geometry Step 5，start仅注册，采样在命令触发后才执行；保留原始日志用于私下审计。
3. 对照原模型身份、单位、222面/126平面和32面结果表；模型名/版本戳/dirty单独不是独立身份或无写入证明，不为命中策略修改模型或精度。
4. 核对QUALITY_CANDIDATE_QUEUE的计划与实际顺序，尤其局部/内部是否在预算内实际执行；若池满或限制提前停，记录原因，不把planned当attempted。常规完整计划应16/8/8，去重/数值范围导致不足如实保留。
5. 所有新点双INSIDE、返回UV精确、有限点/非零法向、单位已知、同面XYZ不重复；边界/域外仍拒绝。qualityAttempts≤32、池≤9、最终≤3、全局3000/900/300/软30秒保持，阈值必须原值。
6. 分别核对32面新增有效点和最终质量改善/未改善/未知/未尝试数量；16个原改善面单独比较是否保持，174个未启用池的面及原4个补采面结果也比较。无改善时保留原3点，不能预填成功。
7. 复算最终XYZ质量及策略计数守恒，区分原生无效与原生有效未选，中间池事件不能重复计点。revision未知、质量不足、限制等继续PARTIAL/UNKNOWN。
8. 异常、模型状态变化或卡住时停止后续测试并保留证据，不Save/Undo/再生/改精度/自动重试。本轮仍不计算厚度，不推进转换，不更改Web、业务命令或Ribbon。
