# 采集后离线审核清单

1. 核对证据ZIP完整性、SHA256SUMS、采集时间、DiskOnly、扫描边界、解码依据与所有issues。缺少进程/JVM/实际加载来源时维持UNKNOWN，不借用云端副本填充。
2. 比对实际磁盘SDK/插件哈希与交付参考，查看是否多个同名不同版本、classpath先后、SDK/本地模块/宿主JVM是否匹配。SDK文件出现两份只代表磁盘发现，不足以判定混装；需已有加载日志/CodeSource或官方只读身份依据。
3. 区分当前磁盘dat/config、注释引用、实际生效配置和已加载模块，结合启动时间/原始配置来源。检查startup模式与同版本官方J-Link/OTK Java兼容、初始化、线程、合法开发/运行许可、解锁/签名要求；本工具不读取许可密钥，也不认证这些条件。
4. 内部WFC反射(long)视图与官方运行契约单独核查。句柄一致、普通PFC读取成功和线程ID一致不能替代官方支持依据。不再以Elements/Element工厂或状态flag现场重试补证据。
5. 对现有jlink/stderr/crash摘要，核对是否同会话、错误标记和类加载顺序。摘要不足时，只离线要求必要的现有材料，不擅自启动新探针、Attach、重启或改日志配置。
6. 已验证Java UI/PFC只读链路可保留；WFC转换继续暂停，直到支持条件与构造方式证据足够。若条件无法满足或在认证条件下仍复现，评估C/C++ Pro/TOOLKIT转换内核：匹配版本SDK/ABI/编译器、合法许可、官方注册/初始化示例、体/面引用与错误处理方案。换语言不是自动修复。

本清单为采集后的判断方法，不是本轮现场结果。采集器不产生“真实转换可用”“许可满足”或“可以清锁重试”的结论，不改任何配置或旧一次锁。
