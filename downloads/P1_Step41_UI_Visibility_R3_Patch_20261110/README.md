# Step41 UI R3：仅替换面计数命令的 SDK 动作键

日期：2026-11-10（北京时间）。本轮唯一变量是 ProCmdActionAdd 的 action_name：p1_readonly_body_face_count → p1_readonly_fc。它是新的短 SDK 注册身份；不修改显示文字、消息键、资源文件、日志功能标识或统计逻辑。

## 1. 改了什么文件

仅 src/entry.cpp 一行：

```cpp
static char name[] = "p1_readonly_fc";
```

只替换 register_readonly_body_face_count 内的这处变量。patches/ui-sdk-action-key.diff 是相同的一行补丁；其余源码逐字节保持 R2。基线 entry_r2.cpp SHA256：a452d16e9a62bcae08fbc49012de90eaba865ece40864d3c6200640764f7f8c4。

可直接使用完整源码，或在隔离副本核对基线后用 git apply --unidiff-zero --check 检查并应用 diff。本包不附任何资源，不复制或重写现场消息文件。

## 2. 为什么改

原始证据已确认：

- R2 源码与交付版逐字节一致，最新初始化段实际顺序为 Body Face Count → Model Info → Ping。
- 最新六项 ActionAdd/Designate 返回均为 0，初始化返回前为 0；列表仍只有 Model Info 和 Ping。
- 面计数已处于首位仍不可见，Ping 在末位仍可见；因此“总是缺末位”的解释未通过，不能再把第三个注册位置当成根因。
- R1 单独缩短消息文件名也未修复。本轮保留 R1 短名及 R2 顺序，不回滚它们。

当前缺失持续跟随同一个命令身份。新的 SDK 键 p1_readonly_fc 长 14 个 ASCII 字符，保留已工作的 p1_readonly_ 前缀，短于可见的 Ping 键；同时取得不同于旧键的注册身份。这个候选测试身份/标识处理或关联元数据，不证明 SDK 有某个字符上限，也不能单次区分“名字长度”和“旧身份关联状态”这两种机制。

命令注册、指定返回成功，只说明调用报告成功；现有观测已经证明不能自动等同于列表可见。包内仍没有本版接口完整文档来证明隐藏条件，故不添加猜测的刷新、图标或菜单 API。

## 3. 预期通过时看到什么

本机助手保持构建参数、SDK Include/Lib、两个 plus 强制引用、R2 注册顺序、访问回调、优先级、标志和资源位置不变，只重编新源码并记录新 DLL 身份。不复用旧对象，也不把旧 DLL 当 R3；不覆盖加载中的文件。

保留 p1_fc.txt 的原字节及其他资源，不改变 DAT 结构或 config.pro。避免旧候选与新候选同时运行或旧按钮直接指向旧动作。沿用既定候选替换流程，不重置全部 UI 设置、不反复重启。

本轮三个标识有意分开：

| 标识 | R3 值 |
| --- | --- |
| SDK action_name | p1_readonly_fc |
| 消息中的显示标签 | p1_readonly_body_face_count（未改） |
| JSON facts.command 功能标识 | p1_readonly_body_face_count（未改） |

现有日志不是对 SDK 注册键的自动回读。BODY_FACE_COUNT_REGISTER_BEGIN 的 command 仍为长名，不表示 R3 未生效；以源码/对象/DLL 身份核对短 SDK 键。本轮不为此增加新 API 或日志字段。如需额外离线佐证，本机助手可只读核对二进制中短键字符串，不执行或加载 DLL。

初始化预期仍为 R2 顺序，六项返回码均为 0，INIT_BEFORE_RETURN=0。然后在相同 UI 显示范围和模型条件下查看 TOOLKIT 列表一次。R2 截图的目标是“备用”模式，之前截图曾是“设计零件”；R3 不再同时切换模式或显示范围来混合解释结果。

记录实际出现的名称：列表可能采用消息标签，也可能采用 SDK 动作名；不要只搜索长名而漏掉 p1_readonly_fc。若新项可见，再按既有流程绑定并点击一次，确认 BODY_FACE_COUNT_ENTER/RETURN 与本候选 load_token 对应。无模型时正常返回 no_active_model，只证明触发路径，不证明面遍历已验收。

若新旧两项同时出现或实际绑定身份不明，先记录名单，不连续点击两项或删除缓存来凑结果。两个旧命令名称和行为不变，不要求额外回归点击。

## 4. 预期失败时如何分支

- 编译/链接、plus 导出或任一注册/指定非 0：先记录候选构建或注册失败；不能与“全部返回 0 但不可见”的条件混合。
- 新短键相关项可见且触发正确回调：支持更换 SDK 身份这一修改在当前条件下有效；不能由此写成已证明某个名称长度上限、保留字规则或缓存实现。
- 项可见但显示的是短名：先记录实际显示契约，不自动改标签；可能是列表采用动作名，不能仅凭名称就判定 ProCmdDesignate 失败。
- 实际新 SDK 键已构建/加载，六项仍 0，但新旧相关项均不可见：单独替换 SDK 键也未通过。停止继续随机缩写或改名；下一轮应基于真实指定文档及消息解析证据再定，不在本轮混改消息键、说明、图标或模式。
- 可见但没有回调日志：区分 UI 可见与实际绑定/触发，保留证据，不修改统计回调来解决 UI 问题。

UI 列表按名称排序，不用行号推断注册先后。只看最新 pid/load_token 对应的初始化和触发记录，不混入文件中 R1/R2 的旧段。
