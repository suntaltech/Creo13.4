# UV有效性依据、数量和失败分支

## 候选与有效点严格分开

GetUVExtents取lower/upper的U/V范围；必须为有限且严格递增、跨度有限。零跨度、反向、无穷/未提供范围均跳过，记录原因，不排序/展开周期区间或用猜测边界填补。范围是参数包络，不证明矩形中任一点在修剪面内。

候选为25个固定内部参数比例组合，先中心、四个四分之一位置，再补齐5×5网格（比例0.125/0.25/0.5/0.75/0.875），先按比例去重，插值后再次按实际UV数值去重，接近浮点退化时可能少于25个。最先3个在正常非退化参数矩形中不共线；这只是数值候选性质，不是曲面上的均匀面积采样或孔边界保证。浮点接近退化时仍以原生判定为准。

每次创建独立UVParams并填写候选；这两个set操作只修改新求值参数对象，不是模型写操作。只有Surface.VerifyUV(candidate)返回PLACE_INSIDE才调用Eval3DData；PLACE_ON_BOUNDARY/PLACE_OUTSIDE/null/其他值/异常一律拒绝，不在边界求值，不通过夹紧UV或外推制造合法点。

Eval3DData后读取GetParams，要求返回UV与候选数值精确一致（正/负零视数学相等），不加未解释的容差、不自动规范化周期参数。差一ULP也会拒绝，属于保守策略，可能少采而不是默认为有效。返回UV再做VerifyUV，仍须PLACE_INSIDE。缺返回UV或GetParams不支持时，不以请求UV替代SDK返回证据。

再读取GetPoint与GetNormal，坐标及原始法向须有限、法向长度有限且非零；记录原法向和稳定归一化值。候选UV按实际浮点值去重；同一面已接受的XYZ若数值完全相同则拒绝重复计点，不用任意距离阈值合并。记录曲面GetOrientation代码但不据其无文档地翻转方向；normalBasis明确为SDK原样。单位来自本轮主长度单位读取，未知时该面不产生经接受的点。单位/体归属等未确认信息不能静默从前一次运行继承。

## “有效”的保证边界

代码保证仅把上述原生INSIDE结果和数值检查全通过的记录标sampleAccepted=true。它不把UV包络中心当域内证据，也不替代PTC内核对修剪域的实际定义。javap只核实API签名和Placement枚举，不独立证明VerifyUV对本机所有修剪/孔/缝模型的行为；首轮真机应人工对照带孔/修剪面和周期面，并保留原生判定。不满足或未核实的分支不标验证通过。

每条接受记录包含请求/返回UV、两次placement代码（INSIDE=0）、有限点、原法向/单位法向、点单位、模型坐标系来源、方向代码与待最终身份核对状态。没有改变模型或独立读取后定位证明的声明；最终模型身份变化会使本轮样本失去后续分析接受条件。

## 失败分支

- 非目标类型不参与采样配额；真实类型读取未知导致目标总分母未知，不能补成0。
- 无单位、UV范围读取失败/无效/退化时，该面0样本并明确stopReason。
- UV参数对象创建/填充失败、请求点非INSIDE、Eval3DData/GetParams失败、返回UV不同/非有限、返回点非INSIDE、点无效、法向为零/非有限均记录SAMPLE_REJECTED及原因；原生异常另保留READ_EXCEPTION堆栈。
- 单面达到3个接受样本即停止该面；25候选耗尽仍不足则保留部分结果，不重复请求相同点直至凑满。
- 全局到300目标面、3000候选或900接受样本时停止进一步采样；未尝试surfaceId集合和原因保留。软预算在循环/求值前及接受后检查，无法中断单次SDK调用。
- 日志I/O失败或流程异常可能只有部分文件；缺终结记录不得视为完整运行。输入身份/dirty或版本戳变化不会自动重采样、Save、Undo或修复模型。

已有采样点不代表曲面全域覆盖；点数量配额不是厚度覆盖率。这里不计算面间距、厚度、可展性或转换方式。
