# 只读分析整改规格

## 第一阶段：消除错误推断

将三件事分开记录：nativeSheetmetalState（原生特征状态）、thinWallShapeAssessment（几何形态评估）、uniformThicknessAssessment（等厚证据）。这是拟议分析结果契约，不修改现有冻结运行schema，也不是声称SDK存在同名API。

- 原生状态只有经核实的原生只读API结果才能写已确认；无API结果为UNKNOWN。STP来源和特征名称只能作来源线索，不可据此写IsSheetmetal=false。
- 目前只有包围尺寸/曲面extent/面积时，薄壁形态与等厚状态为INSUFFICIENT_EVIDENCE。可保留原始读取值并清楚命名为启发式，不能写“已识别等厚薄板”。
- estimatedThickness与suggestedMode均允许null。未知不能默认shell；“已有形态疑似薄壁，需厚度证据，暂不推荐转换方式”优于错误抽壳建议。是否确为疑似薄壁也需明确依据/人工来源，不能所有输入都统一标薄板。
- 候选数改称包络启发式候选数，非真实平面；最小跨度仅称整体包络跨度；用户板厚参数与测量结果分栏，单位未核验时不能硬编码mm。
- 保持转换、保存控件禁止执行；不提供自动shell/driving切换、选面、WCreateFeature/WRegenerate/Save或浏览器写桥。

先修改实际部署源码的相应推断与文案，保持公共接口兼容；不拿历史源码覆盖未知当前实现。交付差分、源文件前后散列和明确的未实现项，Java无需因Web文案整改重新编译。

## 第二阶段：建立可解释的几何读取能力

先盘点真实读取响应，禁止虚构geometry接口或属性。字段不足时，再依据实际Creo13.4 SDK/官方签名设计原生只读几何采集，不调用模型创建、再生或保存。浏览器HTTP已有字段不足以完成可靠识别时，不能通过更换阈值假装补足信息。

拟需几何证据包括真实曲面类型、曲面点/法向、面面积、相邻拓扑、单位与精度、相对面重叠区及沿法向距离。相对平面需在有效重叠区域核对平行性、相对侧和距离；不能只用面心距离、轴向extent差或全局包围盒。折弯区域可能需要对应偏置曲面/半径关系，不能只处理轴对齐平面再推广全模型。

将多处局部厚度样本汇总为候选厚度、离散度、覆盖率、单位/容差及未覆盖区域。容差要依据模型精度和单位设定，不使用未解释的固定阈值。孔、翻边、圆角、厚度变化、局部台阶、开口壳体和曲面体要独立说明；必要时结果为非等厚或无法确认。

即使局部厚度一致，也仅支持相应几何范围的等厚形态证据，不自动证明原生钣金特征、全局可展性或转换可行性。面积比、体积/面积比等统计最多是辅助筛选，不能单独确认等厚。

## 第三阶段：验证与日志

采集脱敏原始响应与浏览器分析事件，按真实Web分析ID关联，不能借用页面导航requestId。记录原生状态来源、几何证据、判断状态、理由、单位、容差、厚度样本覆盖及未知字段；不写虚构成功样例冒充真机证据。

对本案例（导入折弯薄板）首先验收“不再默认推荐抽壳、未知状态显示正确”。等厚识别另行验收，不能用页面显示已改变证明算法正确。

后续样本应覆盖轴对齐/旋转薄板、折弯薄板、非等厚件、厚块、带孔/翻边、曲面体及单位差异；同一几何旋转后分类不应仅因包络方向改变。由真实读取数据验证几何结论，源码静态检查只验证调用范围和逻辑边界，不替代数据或真机验证。

只读成功仍需真实调用集合和模型状态观察；saved:false、无错误、页面绿色提示、模型revision相同均不足以单独证明没有模型修改。任何未知/写调用或模型异常变化需隔离，不用自动Save、Undo、删除来清理记录。
