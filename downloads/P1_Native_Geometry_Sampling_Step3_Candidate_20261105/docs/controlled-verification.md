# 后续审核与受控验证

本轮云端只编译与离线核对，未注册、部署或执行Creo。以下真机动作需在明确受控范围内执行，不改Web、现有业务命令、模型或Ribbon持久化。

1. 校验ZIP.sha256、SHA256SUMS、manifest、本机otk.jar和新8个class/薄JAR身份。运行需Java25；目标major61不表示SDK能在Java17加载。独立目录与类名，不覆盖Step1/Step2或BatchRename；模板路径占位符不可直接注册。SDK/JDK不随包。
2. 先核对新命令Sample Read-Only Geometry Step 3的注册/消息解析及实际新类加载。start只注册，只有未来明确触发才采集；不得用持久化Ribbon写入来绕过入口约束。输出仍可用P1_READONLY_GEOMETRY_LOG_DIR，但文件前缀独立。
3. 用原测试模型核对叶名/实际身份/单位、类型与4面ID，记录新增真实UV范围和数值状态。模型名匹配不是认证同一物理文件；不为命中策略去重命名/改模型或强造类型。
4. 读取TARGET_REFINEMENT_RESULTS、逐面candidate plan及refinement start/summary，核对每面基础≤25、追加≤200、总≤225，接受点仍两次INSIDE。不得把边界/域外放宽为接受，也不为凑点人为改UV返回值或模型。
5. 对四面分别报告实际接受点数和停止原因；未尝试/未找到/读取失败如实保留，不把UNKNOWN改0或成功。全轮仍≤300目标面、3000尝试、900点、30秒软预算；无硬原生调用中断保证。
6. 对平面质量分别看配额、数值非共线和UV/XYZ分散；本轮没有主动替换Step2已接受点，所以不能预期38组问题自动全修复。重点核对新增指标是否与实际坐标相符，不把阈值当官方模型容差或厚度依据。
7. 保留revision null、独立versionStamp及最终模型/dirty检查；即便4面补齐和质量良好，旧严格身份仍可能PARTIAL。模型变化、未知写调用、卡住或异常时停止后续测试，保留原件，不Save/Undo/删除/再生/自动重试。

新增逻辑只使用Step2已有SDK读取接口，UV范围改为基础曲面阶段读取/缓存；没有新增模型变更API、轮廓推断、HTTP或浏览器桥。evidence含完整字节码调用符号核对和真实SDK签名；存在于SDK签名文件的其他方法不等于被调用。

纯测试使用合成数值与真实Step2点的离线算术，无SDK Stub/模型Mock，不生成假的新采样点或运行ID。真实UV域、细化成功与新版质量输出均待本机验证；本包不执行配置恢复或部署。
