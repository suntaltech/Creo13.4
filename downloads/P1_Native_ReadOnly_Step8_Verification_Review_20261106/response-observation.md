# 短时未响应观测

操作者在输入CONCLUSION.md报告：加载命令时短时未响应，随后恢复并出现ended。所附截图只显示恢复后的完成提示，不能用于测定停顿起止或根因。

日志观测区间：

- 采集自身单调计时：7732 ms。
- COLLECTION_STARTED→COLLECTION_SUMMARY墙钟跨度：约7706.943 ms。
- CANDIDATE_CLASSIFICATION_STARTED→SUMMARY：约24.062 ms。
- SDK_READONLY_INTERFACE_REVIEW_STARTED→SUMMARY：约3.988 ms。

各区间起点不包含所有准备/类加载，也没有证明与操作者描述的停顿窗口重合。不能因约24/4 ms就断言新增功能没有任何加载成本，也不能将7.7秒直接称为“加载卡顿持续7.7秒”。缺少注册/Designate/命令进入/Run创建/原生调用/写盘和stderr阶段耗时，以及停顿期间线程或UI响应资料。

后续若专门定位响应，可先在现有受控入口记录上述生命周期时刻、阶段耗时和日志写入量；用相同模型与配置做可比较记录。保留原生调用的SDK线程约束，不未经核对就移到后台线程。逐行flush与stderr镜像等非原生开销可作为测量对象，当前没有足够证据断言它们就是根因，也未实施改动。

本页是事实与待核对方向，不是性能修复、线程修改或现场配置操作。
