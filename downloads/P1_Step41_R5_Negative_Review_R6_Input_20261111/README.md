## 4. 拿到契约后的补丁与判定边界

以下是后续补丁设计约束，并非本包已实现的功能：

- 保持 R5 资源、SDK动作身份、注册顺序、参数、access和业务回调不变。
- 只在文档允许的位置做固定次数消息解析：面计数的 label/help/description 三键，并以一个已可见命令的 label 作为对照；每键一次，不在access或逐面回调中查询，不循环重试。
- 记录原始返回码、可用的有界文本/长度或摘要、调用阶段及身份。缓冲区/变参/失败路径按真实声明实现，输出上界和JSON转义先独立验证，再交本机真实SDK编译。
- 若初始化中额外解析会预热/改变缓存，则明确观察可能产生干扰；不能把随后可见写成已找到稳定修复。

判定分支：

- 文件/键未命中：按真实错误码区分，进一步定位资源与键，不改计数逻辑。
- 对照能解析而面计数键失败：获得命令资源差异证据，再只修确证的一处。
- 所有键均解析且符合当前值，但仍不可见：该解析观测通过，GUI仍失败；不能继续断言消息文件未找到。后续转向有文档支持的命令指定/UI上下文观测，不再重复资源缩写试验。
- 接口只返回文本：只能证明该次调用在其上下文中解析出文本，不能证明 Designate 早先使用同一路径或缓存，也不能反推出语言目录。
- 若必须证明精确路径：另行设计有依据的路径观测，或在单独授权的一变量资源标记试验中辨认；不在消息探针中夹带修改标签/语言/资源。
