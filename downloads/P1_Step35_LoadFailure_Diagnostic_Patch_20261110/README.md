整理日期：2026-11-10（北京时间）。输入证据日期：2026-11-09。

结论：目前不能唯一确定 PRO_TK_GENERAL_ERROR 的根因。证据已支持“DAT 条目被接受、DLL 为 x64、两个入口名正确导出，随后启动/初始化失败”；尚未证明 user_initialize 实际进入。下一轮最小修正是补入口诊断，保持原 ABI、成功返回值和注册字段，不增加注册或业务初始化逻辑。本包是定位补丁，不是已验证的加载修复或正式部署版本。

## 已核实的证据

- screenshot 与 observations.result.json 均指向新条目初始化失败，错误为 PRO_TK_GENERAL_ERROR；新条目未运行，界面仍有响应。没有提出停止请求，因此没有终止回调证据是预期的证据缺口，不能认定终止实现有错。
- headers.log 显示 x64 / PE32+ / DLL；exports.log 中精确出现 user_initialize、user_terminate；dependents.log 只有 KERNEL32.dll。这排除了这些日志所示二进制的明显位数或导出名错误，但不等于云端验证了 DLL 原件或整个 TOOLKIT 装载协议。
- entry.cpp 与 Step32 源码逐字一致：忽略参数，直接返回 PRO_TK_NO_ERROR，没有主动返回 GENERAL_ERROR 的分支，也没有模型或注册调用。
- DAT 为 ASCII，无 BOM，字段只有既定七项；exec_file 基名与日志中的 DLL 基名一致。注册已被接受，路径存在性由现场记录确认。云端不能访问该目录，不将报告的“路径已验证”改写为独立文件系统检查。
- observations 中 DLL SHA256 为 0820a82c17467a7b25ad555960180cd7fd01278ae0831b8dff159fcc27ce31c5；证据包未附 DLL，无法独立复算。截图另有旧应用运行，但没有证据证明它导致此次失败，不停止或修改旧应用。

## 补丁内容

src/entry.cpp 及 patches/entry-step35.diff 仅增加回调内诊断：

- INIT_ENTER：argc 及三个指针是否非空；不记录 argv、缓冲区内容、指针地址或模型数据。
- INIT_BEFORE_RETURN：即将返回 0。这是返回前标记，不声称宿主已接收返回值。
- TERM_ENTER、TERM_BEFORE_RETURN：只有真实终止回调执行时才产生。

每条 JSONL 含 UTC（Z 后缀）、PID/TID、load_token、seq 和诊断 tag。北京时间查看时加 8 小时；不要将输入记录中只有日期的 local 时间伪造为精确 UTC。

日志追加到 Creo 进程 GetTempPathW 返回的目录，文件名 p1-step35-<PID>.jsonl。该目录不保证等于当前终端的 TEMP。文件可能含旧内容，按本轮 UTC、load_token 和 seq 区分；补丁不删除或截断旧文件。文件写入为尽力而为，无强制磁盘刷新或自动重试。

同一诊断行还发往 OutputDebugStringA；补丁不会自动附加调试器。路径/打开/写入等失败会额外发出 TRACE_IO_FAILED 调试标记，恢复调用前的 Win32 LastError，不改变 TOOLKIT 成功返回值。没有文件不能单独证明入口没调用；未采集调试输出时，该渠道也不能事后补出证据。

所有文件/调试操作只发生在两个回调中，没有 DllMain 日志或全局动态初始化 API 调用。日志会增加少量文件/格式化活动，可能影响时序，因此保留原失败基线，不能把诊断版结果直接当作原版完整行为证明。

## 按结果分支

| 后续诊断证据 | 能得出的结论与后续方向 |
| --- | --- |
| INIT_ENTER 与 INIT_BEFORE_RETURN(0) 均出现，界面仍失败 | 已走到用户入口的成功返回前；优先离线核对 SDK 入口/版本协议、样例引导/导出设置及宿主后续校验。不能声称宿主已收到 0，也不凭此判定某一项已是根因。 |
| 只有 INIT_ENTER | 先查日志传输失败、调试输出和异常证据；不能仅从缺一行认定代码死在某条语句。 |
| 没有文件，但有 INIT_* 调试标记/TRACE_IO_FAILED | 入口至少执行到对应标记；先处理诊断通道问题，不能归为“入口未进入”。 |
| 两个渠道均无标记或未完整采集 | 仍可能在入口前失败、加载了其他身份的 DLL，或诊断未被捕获；不能唯一判断。核对 DLL 身份及官方引导契约。 |
| TERM_* 未出现且未成功启动/没有停止操作 | 不构成终止实现失败证据。不得补写“卸载成功”。 |
